## §7 本线打出来的 4 处规则强化（已落地）

### G9：C1e「只写报错」误杀 12 条 → 10 条是错的

原判据：`报错|失败` 且 无 `URL/错误码` 且 实际段 < 15 字 → VAGUE。
hitools 成批出现同一模板：

| 单号 | 标题 | 预期段 |
|---|---|---|
| `#04579` | 配置设备分辨率失败 | AI 意图识别正确 → 生成方案 → **下发成功** → 显示验收结果 |
| `#04718` | 配置视频帧率执行失败 | 同上 |
| `#04906` | 配置码率类型执行失败 | 同上 |
| `#05194` | 配置码率上限执行失败 | 同上 |
| `#03930` | 配置码流时，下发失败（设备本地配置成功） | 同上 |

**修法**：加两道门
- **锚点门**：`hasAnchor = URL | IP | 引号提示语 | {} | codeAnchors` → 有锚点不算「只写报错」
- **期望门**：`expectQuality ∈ {explicit, inferred}` → 期望已唯一就不是「不知道改成什么」

### 引号内容分两类（这是本线最大的坑）

hitools **358 条（56%）** 把用户对 AI 助手的原始指令贴在引号里：

```
“配置设备视频图像夜间模式为自动切换，阈值设置为44”
“配置设备OSD配置添加字符叠加，叠加字符为ACSSDGSDF”
```

第一版把「引号原文」直接当 D1 锚点 → **D1 从 35 飙到 394（62%）**，明显荒谬。

**修正**：
- 引号里是**系统提示语**（含 报错/失败/不支持/找不到/超时/上限…）→ **D1**（可 grep 文案）→ 14 条
- 引号里是**用户输入指令** → **不是锚点**，但它是 ③ 阶段最好的资产 → 新增 `extractReproInput()`

实测：**352 条（55%）能抽出复现指令**；其中与 IP 同时具备的仅 5 条。

### 代码标识符锚点：hitools 独有的强定位信号

标题里可直接 grep 的标识符 **55 条（8.3%）**：

| 标识符 | 出现 |
|---|---|
| `isAPI` | 18 |
| `protocolType` · `smartConfig` · `deviceDeploy` | 各 2 |
| `[interrupt:offline_device_retry]` · `diff_result` · `frontColor` · `barrierFree` · `remainOpen` · `extOverlay` | 各 1 |

**修法**：`locateLevel()` 新增 `codeAnchors()` —— camelCase / snake_case / `[xxx:yyy]` / 全大写常量 → **D1**。
**伪锚点必须排除**：`HiToolsDeliverySetupV2.2.0.1build260923_CN.exe` 长得像 camelCase（`iToolsDeliverySetupV`），
但它指向安装包不是代码 → `PSEUDO_ANCHOR` 排除（`deliverysetup|setupv|hitools|itools|.exe|build\d{6}`）。

⚠️ 同时修了一个连带 bug：`2.2.0.1` 被 IP 正则当成 IP → 版本号误判。已加 `(?<![\d.Vv])…(?!build)`。

### G10：C2「需确认」把有明确动作的标题判成 DESIGN

`#04236`「激活设备生成方案中存在参数名称显示为英文，**需确认**是否有必要展示该参数，**建议显示中文**」
→ 命中疑问句规则判 DESIGN，但标题其实把两个动作都说清了。

**修法**：标题含「建议 X 显示/改为/去掉/隐藏」「应 X 显示/提示」这类**具体动作**时不判 DESIGN；
`建议统一/建议拍板` 这类仍算未定（配套 `#BGJY2026102800081` 仍正确被拦）。
