## §3 `测试环境`：hcp 是「内网 IP + 账号」，与 hc 的「域名 + 邮箱」完全不同

| | hc（300 条） | hcp（212 条） |
|---|---|---|
| 写法 | `UAT11环境（功能主测环境）⏎HCT： https://hc-sgp-uat.../login ⏎ 账号：xxx@yopmail.net / ***` | `RSM环境：10.66.75.99 VSM环境：10.66.75.113  IOS主测（IOS26） fln1  ***` |
| 唯一取值 | 31 种 | **52 种** |
| 可提取 host | **261** | **196** |
| 可提取环境名 | 270（`UAT11`/`UAT1101`） | 156（`RSM环境`/`VSM环境`） |
| 可提取 URL | 261（域名） | **13**（`https://10.67.32.19/#/portal`） |
| 可提取账号 | 299（邮箱） | 14（`admin`/`administrator`/`yf`） |

**`parseReproEnv()` 必须同时覆盖两种写法**，否则 hcp 一个 host 都取不到（第一版只认 `UAT\d+` + 邮箱 → hcp 全空）。
已扩展：环境名认 `RSM|VSM|UAT|DEV|SIT|STG|预发|灰度|生产`，host 认「URL host + 裸 IP(:port)」，账号认「邮箱 + `账号：x` + `admin/administrator/root…` 后跟口令」。

**裁定不变**：`测试环境` 不构成代码定位档（D1），但它是 ③ 阶段的复现入口（内网 IP 直连 `/portal`）。

## §8 结论

1. **结构已稳定**：hcp 与 hc 同为 69 列同一模板，字段规则一套通用，差异只在**词表**（`测试环境` 写法、`测试模块` 取值风格、项目号）。
2. **`[安全]` 池消失**是本批最大的变化（87 → 3）：后续 hcp 分析不必再保留「先剔 87 条」的前置步骤，C7 兜住剩下 3 条即可。
3. **`Open` 单是宝贵的校准资源**：只有在有 Open 的批次里才能证明哪些字段是事后回填。**建议以后每批导出都保留 Open 单，不要只导 Closed。**
4. **①-a 爬到 97.6%，①-b 反而降到 62.7%** —— 两个数的走势相反，说明 ①-a 正在失去区分度（见 `_pipeline.md` 坑 11）。对外只能报 ①-b。
