## §3 四个新增列的裁定

### 3.1 `测试模块`（100% / 52 种）→ **采纳为权威分簇键**

- **97.3%（291/299）与标题前缀逐字相同** → 不是新信息，但**比正则提取更准**。
- 正则提取的 53 个簇里有 **2 个假簇**：`HPP DFX【变更`（嵌套括号被截断，7 条）、`每日总结`（应规范为 `T云视频-每日总结`，1 条）。
- `测试模块` 还补回 1 条标题完全无前缀的单（`BGCM2026082800187`）。
- **结论：分簇从 53（含 2 假簇）→ 52 真簇，修正率 3%（9/300）。** 应把 `clusterFrom` 增加 `testModule` 选项。

### 3.2 `测试环境`（100% / 31 种）→ **复现场景字段：直接解锁 Playwright 复现**

**用户裁定：不脱敏**（内部测试环境，无需担心泄露）。本节仅记录它的**可用内容**，不再作安全告警。

去噪后的真实构成：

| 内容 | 条数 | 占比 |
|---|---|---|
| 模板提示语 + 环境名 + 登录 URL + 账号密码 | 261 | 87.0% |
| 仅账号密码（无提示语） | 38 | 12.7% |
| 仅提示语 | 1 | 0.3% |

**可直接驱动 Playwright 的三件东西（`parseReproEnv()` 已实现提取）**：

```
envName : UAT11                                    （264 条） / UAT1101（263 条）
urls    : https://hc-sgp-uat.hik-connect.com/hc-sgp-uat-11/team/index.html#/login   （261 条）
accounts: 27 个唯一邮箱账号（去重后）
```

- 环境标识：`UAT11` 264 · `UAT1101` 263 · `UAT1108/1109/1110/1111/11811` 各 1~3 条
- 含 `http(s)://` 登录地址：261 条（**§1 里那张 87.0% 的行就是它**）

**三条裁定**：
1. **不构成代码定位档（不加 D1）**——站点登录页能让人**跑起来看到现象**，但推不出代码文件与行。与配套的裁定一致。
2. **它是 ③ 阶段的硬支撑**，也是四条产品线里唯一能**程序化复现**的入口：
   `账号 + URL → Playwright 登录 → 按操作步骤走 → 截图/比对预期结果`。
   这是把 ③ 「补了信息能不能修」从人工估算变成可执行流程的唯一一条路。
3. **可与 `测试项`（若将来有值）复合**：测试项给用例、测试环境给舞台，两者齐全时 ③ 的判定可以自动验证。

### 3.3 `引入活动`（87.3%）→ **参考，不可作硬参照**

| 引入活动 | n | 严格可修率 |
|---|---|---|
| 编码 | 214 | 55% |
| 历史遗留 | 15 | 60% |
| 修改引入 | 15 | 47% |
| 需求 | 13 | **38%** |
| 交互设计 | 4 | 50% |
| 软件设计 | 1 | 0% |

**只作参考的理由**：
- 最大差距 `编码 55%` vs `需求 38%` = **17pt**，且 `需求/交互设计` 合计只有 17 条 → 统计上不成立。
- 它是修复后期回填的，本质上是开发者的事后归因。
- **但它是唯一能解释「为什么这单难」的字段**：看到 `需求`/`交互设计` 就提示“可能是期望未定义”，看到 `编码` 就提示“已定位到代码层”。

→ 代码里放 `REFERENCE_ONLY_FIELDS`，**不进任何硬判据**，只进报告叙述。

### 3.4 `测试项`（0%）→ **可选，有值即测试用例**

本批全空，**不影响结论**。但它的语义很重要：有值时就相当于已经给了「复现用例」，
可以与 `测试环境` 组合成 Playwright 脚本的输入。→ 代码里放 `OPTIONAL_CASE_FIELDS`（不丢、不报错、有则用）。

### 6.1 连带影响：LED 的「8 簇」作废

`LED_PROFILE.clusterFrom` 原本是 `moduleTag`（`所属模块`，9 种）—— **事后字段，聚类本身在偷看答案**。
但 LED 的 65 列模板里**没有 `测试模块`**，标题前缀 309/319 相同（只剩 2 个有效值）→ **LED 在创建时没有合法的模块级分簇键**。

- 已改为 `clusterFrom: "titleTag"`（不再读 `所属模块`）。
- **报告里 LED 不再按模块分簇**，改按 `type`（逻辑/文案与配置/UI还原度/崩溃/性能，由标题+描述算得）分组。
- led 报告里的「8 簇（接收卡 123 / APP业务逻辑 78 / …）」**来源是 `所属模块`，作废**。

配套不受影响：它有 `测试模块` 列（20 种，Cancel 也 100% 填充）→ 应用 `clusterFrom: "testModule"`。
