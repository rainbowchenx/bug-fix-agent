# 已知输入缺口（跨产品线共享前置）
> ⚠️ 本文件中的「可修率」写于 2026-10 上旬，当时口径 = 现在的 **①-a 可定位**。
> 按 2026-10-29 新口径（`_stage1-rules.md`），hc 92.5% → **①-b 严格可修 50.5%**、配套 85.5% → **34.5%**。
> 本文的**缺口结论不受影响**（缺口是「缺什么」，与口径无关），但**百分比请以 `_stage1-rules.md` 为准**。


> 用途：所有产品线的缺陷输入分析都建立在同一组**当前导出能力的限制**之上。这里集中记录，避免每条产品线重复推导，也避免把「工具限制」误读成「缺陷单质量差」。
> 更新：2026-10-27（由 **hc 200 条** + **配套-交通项目 200 条**实测得出）

## GAP-1 手动导出，缺陷描述里测试贴的图全丢

| 项 | 内容 |
|---|---|
| 现象 | 测试人员在 `缺陷描述` 正文里粘贴的截图，导出后只剩文字（连占位符都没有） |
| 影响 | 描述里出现「见下图」「如图」「截图如下」时，**指向的对象不存在** |
| hc 实测 | **33 条**文本引用附件，**缺陷侧附件本体 0 张** |
| 配套实测 | **1 条**提附件（200 条里仅 1 条，且正文自足） |
| 误判风险 | 会把「有图但没导出」误判成「描述不清楚」 |

## GAP-2 缺陷单的附件（图片/视频）不在导出里

| 项 | 内容 |
|---|---|
| 现象 | 缺陷平台上的附件（截图、录屏、日志、抓包）不属于 65 列的任何一列 |
| 影响 | 「见附件」「见附件视频」「见附件录屏」「看群里发你们的」全部**悬空** |
| hc 实测 | 33 条引用中，**依赖型 0 条**、佐证型 33 条（正文均自足） |
| 现有唯一可用证据 | `缺陷描述` 里测试手贴的 `pagespy/…/replay?url=` 录屏链接（hc 200 条里仅 1 条） |

## GAP-3（易踩的坑）`缺陷处理说明` 里的 `<img>` 是修复后截图，不是缺陷附件

| 项 | 内容 |
|---|---|
| 现象 | 该字段内嵌 HTML：`<img src="…/attachment/unauthorized/download?fileId=…&key=…">`，**带 key 可直接下载** |
| 性质 | **开发者修复后的验证截图**（字段本身是闭环字段，`Open` 单 0/20 有值） |
| 危害 | 展示的是「修好之后」的界面。当成缺陷证据输入 → 会得出「看截图，界面正常 → 该缺陷不成立」的**反向误判** |
| hc 实例 | `#110`：描述「见截图」指截断的坏样子，`缺陷处理说明` 里那张是修好后的好样子 |
| 处置 | **与 `解决方法` / `验证结论` 同级列为 forbidden 字段**，不进上下文、不进报告引用 |

## 对判定口径的影响（写进每条产品线报告的前提）

1. **当前「可修」= 文字自足性**，不是「信息充分性」。附件将来可读后，这个数会变。
2. hc 200 条的 **92.5% 可修率**与附件基本无关（依赖型 **0 条**）：
   - 33 条「佐证型」的正文已自足 → 附件可读后**可修率不变**，只是这 33 条的**置信度**可从 medium 升到 high
   - 真正受影响的是「隐性视觉依赖」（如 #36 名称超出屏幕、#44 日期乱码、#47 按钮溢出）——文字能定性，但「正确样式」要图
3. 因此报告里必须显式声明：**「本次分析未获得任何附件」**，并单列一条 `evidenceGaps: ["attachment"]`（对应 `CONF-4` evidenceGaps 非空 → 置信度上限 medium）。

## 附件可读之后要回填的三件事

| # | 动作 | 影响 |
|---|---|---|
| 1 | 确认「依赖型 0 条」是否成立（hc 200 + 配套 200） | 可修率**不变**（hc 92.5% / 配套 87.5%） |
| 2 | 把 33 条佐证型的置信度从 medium 提到 high | 报告 `byConfidence` 分布变化 |
| 3 | 附件类型纳入路由：`视频/录屏` 可读 → 可提取动作序列；`图片` 可读 → 可提取 UI 状态与文案；两者都不等于「可直接修」，仍需定位 | 影响 `suggestedAction` 中 `needs_runtime_info` 的比例 |

## 导出侧建议（等业务侧支持时按此提）

1. 附件单独成列：`附件URL[]`，并区分 **缺陷侧附件** 与 **闭环后附件**（后者不要给）
2. `缺陷描述` 保留内联 HTML 原文，别 strip 标签（否则连图的位置信息都没了）
3. `缺陷处理说明` 里的 `<img>` 明确标记为「修复后证据」，与缺陷侧附件分流
4. `pagespy/…/replay?url=` 识别为测试侧录屏，单独标注类型
