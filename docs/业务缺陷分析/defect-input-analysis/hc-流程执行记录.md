### 降级替代方案（三条自证）

| 手段 | 做法 | 局限 |
|---|---|---|
| **同族一致性** | 同一簇的 N 条缺陷是否都指向同一落点（如「每日总结」8 条 → 同一套餐判定函数） | 只能证「一致」，不能证「正确」 |
| **代码自证** | 必须能指出「缺失的分支 / 未初始化的变量 / 漏加的条件」，而不是「这里看起来可疑」 | 无法覆盖时序类 |
| **交叉自证** | 两条独立缺陷指向同一文件同一函数 → 互为旁证 | 同源缺陷不算独立 |

### 若要恢复可验证性，需要什么

| 需求 | 说明 |
|---|---|
| 带 `.git` 的拷贝 | 哪怕只含 `--depth=200` 的历史，就能恢复 `git log -S` |
| 更接近缺陷月份的副本 | 现有是 2026-03-03，缺陷在 2026-09 → 中间 6 个月的功能全部缺失。**理想是 2026-08 下旬** |

> 只要这两条任一满足，S8 就能做；否则 hc 的 S7 结论只能标注为「单快照静态定位，未经外部校验」。
