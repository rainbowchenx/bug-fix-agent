## 3. C 判定规则

**判据范围（v1 新增，关键）**：`C1`/`C4` 只看**标题 + 实际结果段**（下称 sig），不看预期结果段。
因为预期结果常是标准话术——本批 26 条写的是「不存在遮挡、未翻译、显示不全等情况」，直接扫全文会把 3 条可修缺陷误杀（#33 #34 #35）。

### C7 生产者分流 → `SCA` / 安全通道【可编码】

`检出工具|软件成分分析|静态检测|hikshield|漏洞名称` → 安全通道；含 `CVE-\d|CVE漏洞` → `SCA`（依赖升级，非代码）。本批 **0 条**。

### C3 归属非代码 → `NOTCODE`【半可编码】

| 模式 | 含义 | 本批命中 |
|---|---|---|
| `启用控件` / `无插件[≤20字](无法播放\|黑屏\|不能播放)` | 浏览器插件依赖（产品设计如此） | **4 条**：#11 #18 #19 #20 |
| `不要写死\|写死` | 实现方式建议（非缺陷） | 1：#82 |
| `脏数据\|环境问题\|环境异常` | 环境/数据 | 0 |
| `产品已有结论\|需要后续优化` | 产品决策 | 0 |
| `服务[≤8字]异常` | 服务故障 | 0 |
| `还是旧的\|改回旧图\|要不要替换图片` | 资源待替换 | 0 |

> ⚠️ 两个坑：① 单独的「无插件」可能只是**模式名**（本批 #24「集中监控无插件…回放没有云存储选项」= 真缺陷），必须要求伴随「无法播放/黑屏/失败」；② 「环境不可用」多是**线上功能坏了**（#14），不是环境问题。

### C2 期望未定义 → `DESIGN`【需模型】

信号：疑问句 /「是否需要」/「请确认」/「建议统一」/「以哪端为准」/**标题前缀 = `需求变更`**。本批 **2 条**：#21（「没开AI套餐的时候，是否不展示AI搜索按钮」）· #52（「确认下…这些地方是否需要翻译为小语种」）。

### C4 运行时依赖 → `RUNTIME`【半可编码】

`sig` 含崩溃/闪退/白屏 **且** 概率词（偶现/偶发/概率/偶尔）**且** 无堆栈 → `RUNTIME`；或含「老设备 / x.y.z 老」；或「特定机型 + 其他机型未复现」。本批 **0 条**。

### C5 附件依赖 → `ATTACH`【可编码】

**v1 收紧**：只在**附件不可得**时判依赖 —— `看群里|群里发|上传失败|没法上传|附件传不`。
「有附件但导出没带」= 佐证型，不降级（否则会误杀本批 #41「见附件录屏」这类正文已说清楚的）。

### C1 不可断言 → `VAGUE`【需模型（词表约覆盖 2/3）】

在 `sig` 上判，且**崩溃/白屏豁免**（崩溃本身可断言）：

| 子规则 | 触发 | 本批 |
|---|---|---|
| C1a 空模板 | `包括复现方法和现象描述等` / `预期结果：` 后直接接 `问题：`(无实际结果) | 0 |
| C1b 标题称崩溃但正文无崩溃信息 | 标题有崩溃词、正文无、正文 <60 字 | 0 |
| C1c 纯形容词无量化 | `展示异常` `页面偏移` `兼容(有点)问题` `较多…未更新` `显示不全` `间距问题` `多了一个` `结果异常` `显示有问题` `格式有问题` `页面异常` `待优化` … | **8 条**：#13 #42 #74 #76 #170 #188 #191 + #98 |
| C1d 性能无量化 | `较慢|很慢|加载慢|超时|延迟|需要一定的时间` 且无 `\d+(秒|分钟|ms)` | 1：#98 |
| C1e 报错过短 | 含 `报错|失败` 且实际结果段 <15 字且无 URL/错误码 | 0 |

> 「不一致」需区分：**给了两端对照**（`Android…iOS…` / `右侧…左侧…` / `与Portal不一致`）→ 可修；只写「不一致/上下不一致」→ `VAGUE`。

### C6 多问题混写 → 标记（不影响判定）【半可编码】

`问题1：…问题2：…` 或以「且/同时」连接两个可独立验证的现象 → `multiDefect=true`，拆多条 `openQuestion`。本批 **0 条**。

### 默认 → 可修

本批 **185 条（92.5%）**。

## 7. F 口径规则 & 执行伪代码

| ID | 规则 |
|---|---|
| **F1** | 可修率必须绑定仓库边界与业务组：本批 86% 是「HC 单一业务组 + 全端仓库」口径 |
| **F2** | 附件缺失 → `evidenceGaps:["attachment"]` → `CONF-4` → 置信度上限 **medium** |
| **F3** | D3（仅功能点）→ 置信度上限 **medium**；D1 且无缺口 → 可达 high |
| **F4** | 措辞：可修 = **编译级可交付**，禁止写「已验证修复」 |

```
run(defects):
  mark_duplicates(defects)                          # A7
  rows = strip(defects, FORBIDDEN_CLOSED)           # A1..A5
  for r in rows:
     if is_scanner(r): r.channel = security         # C7
  clusters = group_by(normalize_tag(tag_of(t.title)))  # B1 B2 (+B3/B4 需模型)
  for c in clusters:
     sig = c.title_bare + actual_segment(c.desc)    # 判据范围（D5）
     if is_not_code(c):        action = NOTCODE     # C3
     elif is_undecided(c):     action = DESIGN      # C2
     elif needs_runtime(c,sig):action = RUNTIME     # C4
     elif attach_unavailable(c): action = ATTACH    # C5
     elif is_vague(c,sig):     action = VAGUE       # C1
     else:                     action = FIXABLE
     c.multi = is_multi(c)                          # C6
     c.type  = classify_type(bare_title, actual)    # E
     c.dlevel= locate_evidence(c)                   # 5.3
     c.conf  = confidence(c)                        # F2 F3
```

## 10. v1 → v2 的六类失误（来自「首次未见 150 条」的真实泛化测试）

规则在 50 条上定型后直接跑另外 150 条，verdict 只有 **134/150 = 89.3%**，16 条失误集中在 6 类：

| # | 失误 | 条数 | 根因 | 修正 |
|---|---|---|---|---|
| 1 | 「**不正确/不准确**」被当含糊词 | 6（#119 #125 #136 #140 #179 #192） | 这类词多数已指明「哪里不对」（如「提示是 Camera，不正确」「实际密码正确」），属**可断言** | 从 `VAGUE_ADJ` 移除 `不正确`/`不准确`，只保留「展示不正确」这类真含糊 |
| 2 | 含糊短语没覆盖 | 5（#76 #98 #170 #188 #191） | 「显示有问题」「格式有问题」「页面异常」「待优化」「需要一定的时间」不在词表 | 补入；性能类补「需要一定的时间」 |
| 3 | 「**无插件**」再次误判 | 2（#88 #89） | `无插件…失败` 命中了「无插件**导出**…导出失败」——这是导出逻辑缺陷，不是插件问题 | 收紧为 `无插件+无法播放/黑屏/不能播放`（去掉裸「失败」） |
| 4 | `DESIGN` 用了全文匹配 | 1（#52） | 模板里的「校验新增界面**是否翻译**」被当成疑问句 | `DESIGN` 也改用 `sig`（标题+实际结果段） |
