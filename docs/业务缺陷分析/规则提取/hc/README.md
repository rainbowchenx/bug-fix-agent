# 规则提取

按**产品线 + 业务组**沉淀从缺陷单实测中提炼出的判定规则。每条规则必须带「实测命中数 + 反证条目」，能被复核、能被推翻。

```
规则提取/
└── hc/                      Hik-Connect 7.0.0（hc1..hc4.xlsx，200 条唯一，单一业务组）
    ├── README.md            本目录说明、状态、下一步
    ├── rules.md             规则正文（41 条：可编码 25 / 需模型 11 / 禁止 5）
    ├── evidence.md          每条规则的实测依据 + 反证行号
    ├── baseline-labels.csv  200 条人工判定基线（校验用）
    ├── fixtures/            xlsx → json 的原始记录（规则跑批输入）
    └── check-consistency.ts 一致率校验脚本
```

## 状态

| 产品线 | 样本 | 规则版本 | 基线 | 实现 | 同批回测 | 留出验证 |
|---|---|---|---|---|---|---|
| `hc` | **200 条唯一**（`hc1..hc4.xlsx` 各 50，ID 无交集） | **v2**（41 条） | 185 可修 / 15 不可修 | `src/defects/` 已实现 | verdict 200/200 · reason 200/200 · 类型 170/200 | **首次 150 条 = 89.3%**（修完后已污染） |

> ⚠️ 唯一可信的泛化读数是 **89.3%**（规则在 50 条上定型后，首次跑另外 150 条的结果）。之后为修那 16 条失误调了规则，这 150 条也变成调参集，所以 200/200 只是训练集一致率。**下一批全新导出必须重跑留出验证**，仍低于 85% 即视为过拟合。

## 怎么跑

```bash
npx tsx 规则提取/hc/check-consistency.ts          # 一致率
npx tsx 规则提取/hc/check-consistency.ts --verbose # 附逐条差异
```

> 需要 `node_modules`（`npm install`）才能跑 vitest；`check-consistency` 用 `npx tsx` 可直接跑。

## 版本沿革

| 版本 | 样本 | 结论 |
|---|---|---|
| v0（废弃） | 4 文件 × 50 条「混合业务组」（含 app/硬件/AX PRO） | 得出「AI-Agent 占 42%」等结论，实为样本污染 |
| **v1** | `hc1.xlsx` 50 条，单一业务组（融合云业务测试组） | AI-Agent 归零、i18n+UI 占 44%、D1 定位证据仅 4% |
