## 口径约定（重要）

**87 条 `[安全]` 单整体剔除，不计入任何修复率**（85 SCA 依赖 CVE + 2 iOS 静态检测）。
分母 = **159**。`tier2-classification.csv` 里用 `tier=剔除` 标记，`run.ts` 也应先过滤。

## 与 hc 画像的差异（待建 `HCP_PROFILE`）

1. **必须前置拆分安全单**：`title` 以 `[安全]` 开头 87 条，其中 85 条是 `[软件成分分析]` 依赖 CVE。
   现有骨架靠 `SCA` 规则能正确判出 85 条（类型 `安全-SCA`），但**会把 2 条 iOS 静态检测判成可修**，实际 iOS 代码不在本仓。
2. **【安卓】前缀 16 条 = APP 端出仓**，建议加 `notcode` 规则：`/^【安卓】|^【安卓和IOS】/ → "Android/iOS 端代码不在本仓"`。
3. 类型准确率偏低（40 条抽样人工核对约 **75%**，低于 hc 的 85%），主要错法：
   - 样式类（cursor 未变小手、蒙版距边界）→ 判成「逻辑」，应「UI还原度」
   - 提示缺空格 / 提示内容缺字段 → 判成「逻辑」，应「文案与配置」
   - 状态未重置（锁定时间、二分法间隔）→ 判成「权限与数据」，应「逻辑」
   → 需要 `typeHints` 补：`/鼠标[^。]{0,8}(小手|指针|样式)/ → UI还原度`、`/缺少空格|空格缺失/ → 文案与配置`、`/默认为上次|未重置|不重置|被重置/ → 逻辑`
4. 分簇：标题前缀只有 9 种（模块编码 `A03_BS_预览`/`B02_BS_回放`/`CC03_访客管理`…），
   可用 `clusterFrom: "titleTag"`（默认），但建议先按 `[安全]` 与非 `[安全]` 分池，避免安全单把簇拉歪。

  **注意这是下界**——hcp 的修复提交信息极笼统（`fix:3.2协助无插件系统测试缺陷修复`），
  用 `git log -S <代码特征串>` 复核可发现更多（抽查 3 条未命中全部实为已修）。
