# expectQuality 实测（四条产品线）

`verdict.ts` 新增正交字段 `expectQuality`：回答「知不知道改成什么」，与 `verdict`（能不能定位）分开。

```
严格可修 strictFixable = verdict === FIXABLE && expectQuality ∈ { explicit, inferred }
```

## 实测

| 产品线 | n | ①-a 可定位 | ①-b 严格可修 | expectQuality 分布 |
|---|---|---|---|---|
| **hcp**（安全单已剔） | 159 | 151（95.0%） | **104（65.4%）** | explicit 108 · ambiguous 29 · absent 21 · inferred 1 |
| hc | 200 | 185（92.5%） | **101（50.5%）** | explicit 98 · ambiguous 51 · absent 46 · inferred 5 |
| 配套-交通项目 | 200 | 171（85.5%） | **69（34.5%）** | explicit 75 · ambiguous 54 · absent 65 · inferred 6 |
| led-客户端 | 319 | 312（97.8%） | **220（69.0%）** | explicit 219 · ambiguous 62 · absent 33 · inferred 5 |

> 配套偏低是因为它的标题极短（「雷达页面缺少停止标定接口」），规则会把「缺少」判成 ambiguous；
> 人工看这类其实期望唯一（应该有这个接口）。所以 **规则值是参考值（±10pt）**。

## 校准（hcp 40 条人工判读 vs 规则）

| 我的判定 | n | 规则判 strict | 一致 |
|---|---|---|---|
| A | 25 | 20 | **80%** |
| B | 6 | 3 | 误判 50% |
| C | 5 | 1 | 误判 20% |

## 四档定义与判据

| 档 | 判据 | 例 |
|---|---|---|
| `explicit` | 预期段有效（非空 + 非通用通过标准 + 非抄标题 + 与标题有实词交集）**或** 单子给了对照基准/具体值 | 「点击编辑钥匙可以打开修改弹框」·「插件下有这个功能」·「与550基线不一致」 |
| `inferred` | 标题自带方向词（应/需/改为/显示为/置灰/禁用…） | 「再次添加锁时默认的锁定时间应重置」 |
| `ambiguous` | 有对象有现象，但目标不唯一 | 「锁图标与页面其他图标风格不一致」（该对齐哪个？）·「单窗口放大没有主码流」（强制还是保留？） |
| `absent` | 连现象层都不够 | 「有2处异常展示」·「显示异常」 |

## 已知边界

- 「与 X 不一致」判 `explicit`（X 是参照物，目标=对齐 X）；但「与**预期**不一致」不算（预期本身没给）。
- 「A 没有 B」判 `ambiguous`（知道缺 B，不知道 B 该长什么样）；若同时给了基准（插件下有）则 `explicit`。
- 规则不编码「代码在不在仓」——那是 ② 能力口径的事，不是期望唯一性的事。
