> 提炼方式：逐条人工判定 200 条 → 与 hc 规则做差 → 差异收敛到 `TRAFFIC_PROFILE`（`src/defects/profile.ts`）。
> 回测：**verdict 200/200 · reasonCode 200/200 · 类型 197/200（98.5%）**。
> 版本沿革：v1 = 150 条（1–4 文件）；**v1.1 = 200 条（+文件 5 的 50 条）**，新增 6 条 VAGUE/DESIGN 判据与 9 条类型词表。

## 3. 判定（C 组）

### C7 生产者分流（**本产品线新增一类**）

| 命中 | 判 | 条数 |
|---|---|---|
| `软件成分分析｜产品漏洞扫描｜漏洞扫描` **且** `CVE-\d｜HIK-VUL｜安全漏洞｜Double_Free` | `SCA`（依赖升级/固件补丁，非业务代码） | **11**：#8 #9 #10 #93–#100（11 条 / 200 = 5.5%） |

> hc 的 C7 只认 `扫描器 + CVE`。配套有 **`HIK-VUL-222_RTSP_Double_Free`** 这类**不带 CVE 号**的固件漏洞 → hc 规则会漏，profile 补 `scaVuln`。

### C3 归属非代码

| 规则 | 本批命中 |
|---|---|
| 内置（脏数据/服务异常/资源待替换/写死） | 0 |
| **本产品线新增**：`提示信息建议｜建议做在｜建议放在｜建议移到` = 交互实现建议 | 1：#17 |
| **本产品线禁用**：`启用控件｜无插件+无法播放/黑屏/不能播放` | **禁用**（见下） |

> **「无插件」在配套不是 NOTCODE**。hc 里「火狐无插件播放不了」= 产品设计如此（4 条不可修）；
> 配套的「无插件」是**测试矩阵的一维**（有插件/无插件都测），缺陷实质是「两种模式下表现不一致」→ 可修逻辑缺陷。
> 例：#56「无插件下切到交通统计直接显示信息，有插件下要再点修改参数」→ 逻辑。#61 #62 #4 同理。

## 4. 禁止规则（D 组，含被数据推翻的）

| 禁止 | 状态 |
|---|---|
| **D1 用描述长度做阈值** | 反例：最短 20 字「海外微卡目标停留时间单位应修改为S」**可修** |
| **D2 提附件就放弃** | 本批 **0 条**提附件；hc 33 条提附件、0 条因此不可判 |
| **D3 严重级别排优先级** | `高` 3 条全是 CVE/安全漏洞，业务缺陷全在 `中`(114)/`低`(33) |
| **D4 「与基线不一致」一律判不可修** | 21 条信息充分，只是对照物在外部 → 判可修 + `evidenceGaps:["baseline"]` |
| **D5 预期结果段当现象** | 配套 25 条预期结果是模板话术，扫全文会把「与550不一致」判成含糊 |
| **D6 空模板一律判不可断言** | **被数据推翻**：22 条「实际结果」为空，**21 条标题自足**（如「已用内存与实际不符」「缩放150%，图片查询被遮挡」）→ 退回只看标题 + 记缺口降置信度 |
| **D7 「需确认」当不可修** | 只在原文明确写「需确认**需求/是否合理**」时判 `DESIGN`（4 条）；「需与550保持一致」给了对照基准 → 可修 |

## 5. 类型（E 组）

**按「缺陷作用的代码层」判，不按业务词。**

| 优先级 | 类型 | 判据 | 条数 |
|---|---|---|---|
| 1 | 安全 | SCA（扫描器+CVE/HIK-VUL）· 密码策略 | 12（6%） |
| 2 | 文案与配置 | `未翻译/英文/中文/繁体/词条/单位错误/名称/大写/提示内容/内容错误` | 24（12%） |
| 3 | UI还原度 | `遮挡/空白/显示不全/自适应/缩放/150%/顶格/换行/闪烁/示意图/明文显示符/UI异常/太小` | 40（20%） |
| 4 | 逻辑 | 其余（分支/校验/状态/接口参数/多余或缺失控件/**为空·无选项**） | 124（62%） |
| — | **兼容性 = 关闭** | 本产品线 0 条；hc 的 `机型/浏览器` 规则会把「海外TCM机型…多了页面」误判 | 0 |
| — | **权限与数据 = 关闭** | 本产品线 0 条；`未隐藏``入口` 规则会把「出入口界面」误命中 | 0 |

**四个需要说明的边界**：

1. **`密码明文显示符` → UI还原度，不是安全**（#126 #133）：缺的是输入框上的「小眼睛」控件。
2. **`缺少提示框` → 逻辑，不是 UI**（#28 #33 #135 #140）：缺的是分支里的提示逻辑，不是布局。
3. **`下拉框为空 / 无选项 / 增强级别为空` → 逻辑**（#131 #176 #177 #183）：选项是数据，不是布局。
4. **`默认为四分框` / `缺少屏幕分割比例控件` → 逻辑**（#111 #184 #185）：缺控件与默认值是取值逻辑；曾误判为 UI，本版修正。

## 9. 待验证

1. **留出验证未做**：200 条里 199 条此前已阅读（本轮 50 条也是「先读后判」）。需一批全新导出（≥40 条）原样跑，不改规则。
