# 数据准备与验收清单

| 数据 | 准备内容 |
| --- | --- |
| 原始缺陷导出 | CSV 或契约格式 JSON，保留票号、标题、原文、状态、模块、复现步骤、实际与预期、截图路径。保留首轮输入原有缺失。 |
| 业务仓基线 | 记录 HEAD、仓型、运行环境和验证命令。截图与日志须能从实际执行机访问。 |
| 人工真值 | 独立记录归属仓、合理定位、已知根因或未知点、验收行为和验证方法。运行后再交评分人。 |
| 二轮反馈 | 挑 8–12 张真实反馈票，覆盖纠正预期、补复现和补截图。补丁应用与业务回归另用至少 20 张独立标注可修票。 |

样本覆盖路径明确、跨模块、信息不足、依赖截图或环境、外仓缺陷。

- [ ] Agent1 输入票号与数量可对账。抽查筛选、分簇和票面切片。
- [ ] Agent2 检查 code-knowledge.json 及调查记录，核对 SDK 来源、逐票状态、候选路径和证据。
- [ ] Agent3 检查 analysis-report.json，核对逐票结论、应走 SDK 的分析来源、定位、根因、阻塞原因及附件读取。
- [ ] 反馈后记录用户补充是否被消费、是否重复追问、是否推进到合理结论或候选。
- [ ] 补丁验收记录能否应用、实际业务回归和本地提交 SHA。
- [ ] 批次总结分别记录流程完成、人工分析正确和补丁验收通过。

参考 [Agent1 评测](../agent1/README.md)、[Agent3 评测](../agent3/README.md)及 [现有评测模板](../agent3/templates/)。
